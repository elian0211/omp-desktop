# Project navigation (#27, reworked by the 2026-11-21 project-dock layout)

Tabs are grouped by **project = (profile, folder)** (a **workspace** is that folder): `src/app/project-nav.js` (`window.OMP_PROJECT_NAV`, regression `test-project-nav.mjs`) is the single definition, shared by the **project strip** (`design/project-strip.jsx`), the **project side**'s Sessions fold (`design/project-side.jsx`), the thin session tab strip (`design/chrome.jsx` `TabBar`), the history panel's per-project filter chips (`sessionProjects`, #35 — saved sessions are already one profile's, so the folder alone is the key) and `live.js`'s focus-existing lookups. Paths compare via `normPath` (slashes, trailing slash, case only for Windows drive/UNC paths); pathless tabs never group.

## Chrome (under a full-width title bar and toolbar)

- **Project strip.** Far-left column (`ProjectStrip`): one button per open project — a 2–3 letter abbreviation of the project's display name (`projectAbbr`; the stored `label` override, else the folder name) over the project's appearance accent (`OMP_PROJECT_APPEARANCE`, falling back to muted), the group's run state as a `TabRunDot` badge, active project ringed. A picked accent is the button's background at full strength with the ink chosen against it (`OMP_PROJECT_APPEARANCE.inkFor`, WCAG contrast — the palette accents keep the dark ink, a custom dark colour flips to light); the default muted mix keeps the window's own ink. Hover/accessible name is the label (when set), the path (+ profile label). Click focuses that project's target session (`groupTarget`: the active member, else the newest); right-click opens a small menu — **Edit project…** (the modal's edit mode) and **Reset appearance** (drops the project's whole override, the Settings row's reset), both `useMenuPick` popovers portaled to `<body>` (branch-menu's pattern). The bottom `+` opens one recents menu — the recent list (rows show the stored label) plus "new project…" (the single recents surface; `handleOpenRecent`/`handleForgetRecent`).
- **Project side.** Resizable panel beside the strip (`ProjectSide`, width `sidebarWidth`, `desktop.sidebar.toggle`/`Ctrl+B`), with two independently collapsible folds (window-global `sideFolds`): **Sessions** — only the active project's tabs, `membersNewestFirst`, with run dots; click focuses/opens the tab (the primary way to move between conversations), × closes, double-click or the pencil renames, "new conversation" as the fold header's plus icon (beside the title, like the Explorer's filter icon), drag reorders within the project, and a row's right-click menu offers rename, **archive** and **delete** (delete confirms inline in the row). Archive/delete need a persisted session file and a non-busy agent (disabled otherwise, reason in the tooltip): the handler closes the tab first — its omp process must no longer hold the file — then `session_archive`/`session_delete` (`saved_sessions::ops`) run under the tab's own profile. omp's RPC has no archive/delete, so the Rust side mirrors ompweb's file-level semantics: archive writes omp's `gc --archive` layout (`<agent>/archive/sessions/<relative>.jsonl.gz`, artifacts directory — same name minus `.gz` — moved alongside, atomic with rollback), delete unlinks the file and removes the artifacts best-effort; both re-check the path against the sessions root. A failure after the close surfaces as a note in the now-active tab — and **Explorer** — the `FilesView` tree, fetching while the side is open and the fold expanded; its name filter stays hidden until the fold header's search icon opens it (closing clears the text); selecting a file opens the tool dock's **File** preview (`handlePreviewFile`), not the stage files-detail panel (commenting still handoffs from the preview header).
- **Thin session tab strip.** `TabBar` moved under the toolbar into `.main-column`: only the active project's open sessions (no project chips as switcher — the `TabGroupChip` retired with the strip). Click focuses, middle-click/× closes, drag reorders within the project, Settings stays pinned last.
- **Tool dock.** Far right vertical text tabs (`design/tool-dock.jsx`, state `app/tool-dock.js`): File / Session / Tree / Usage, one pane at a time, re-click collapses; see `file-preview.md`, `pr-automation.md` and below for what each hosts.
- The activity-bar three-view navigator (Workspaces / Files / Session, `OMP_ACTIVITY`) is **retired** — its parts live on as the strip, the Explorer fold and the Session dock pane; `app/activity.js`, `design/activity-bar.jsx` and `design/workspaces-view.jsx` are deleted.

## Sessions & tabs

- A tab is still one omp session/process; nothing here changes registry identity (`session-model.md`).
- **Member order.** The Sessions fold and the thin tab strip list members in reverse registry order (`membersNewestFirst`, #38), so a newly opened conversation comes first. Display only: `sessionRegistry` keeps opening order (or the dragged one, below), which `groupTarget`, `open-tabs.json` restore and `closeSession`'s next-active choice read.
- **Reorder (#40).** Drag a conversation within its project in the Sessions fold or the thin tab strip (no project-level drag on the strip — the strip's order is `groupTabs`' registry order); `Ctrl+Shift+PageUp`/`PageDown` (`desktop.tab.moveLeft`/`moveRight`) move the active tab within its project. `OMP_PROJECT_NAV.moveGroup`/`moveMember`/`shiftGroup` compute the new tab order — every project contiguous, which `groupTabs` renders the same — and `OMP_BRIDGE.reorderTabs(ids)` rebuilds `sessionRegistry` in it, applying only an exact permutation of the open tabs (a stale snapshot is a no-op); `notify` then persists it to `open-tabs.json`, so the order survives a restart. A member drop is in display order, the registry's reverse: a drop above a row is a registry move behind it (`handleReorder` in `app-live.jsx`).
- **Drag mechanics** (`design/ui/use-drag-reorder.js`, geometry `app/drag-reorder.js`): pointer events, not HTML5 drag and drop — chosen while Tauri's native file drop (`dragDropEnabled`) still swallowed HTML5 drag events on Windows; it is off since the composer's image drop (#50), and pointer events stay for the threshold, Escape and capture. Items carry `data-reorder-list/-id/-axis`; only items of the pressed one's list are targets, so a member never lands in another list. A press becomes a drag after 5 px, so a click still selects; the click a drop produces is swallowed, Escape cancels, and the pointer is captured on the item. Controls inside an item (×, rename, an inline input) never start a drag. `.session-tabs` is outside `.chrome`, so a tab drag never reaches the window-drag handler.

## Recents & opening

- **New project** (the strip's `+` menu row, the toolbar's open button, `desktop.tab.new`, the empty workspace): a modal (`design/project-open-modal.jsx`, `bridge-scrim` + focus trap like `confirm-close.jsx`; pure draft transitions in `app/project-open.js`, `OMP_PROJECT_OPEN`) over three fields — folder (typed absolute path or the native picker via `open_project`), display name (defaults to the folder basename), accent (the Settings `ACCENTS` palette or a hex). A hand-typed path is validated by `project_folder_validate` (`external_open::canonical_folder` off the IPC thread): it must exist and be a directory, the error is the modal's inline message, and the canonical result — like every OS-sourced path — is what the patch and the spawn use. Commit writes the `projectAppearance` patch (only what differs from the defaults in open mode; both fields in edit mode, so erasing one resets that half) and then `openProject`: an open tab on that folder under the active profile is focused, else one spawns — same semantics as a recents row. Spawn failure after validation keeps the existing rollback/note path.
- **Project names are display-only overrides.** `projectAppearance` entries carry an optional `label` (keyed by the same `normPath` absolute path as theme/accent, localStorage tweaks; read `OMP_PROJECT_APPEARANCE.forProject(path)?.label`). Every surface prefers it and keeps the real path in its tooltip: the strip's abbreviation and accessible name, the recents rows and the Settings → Appearance project row. Renaming never touches the disk, the grouping or `open-tabs.json` restore.

- Recent projects live in `<app config>/recent-projects.json` (`src-tauri/src/recent_projects.rs`), one list keyed per entry by profile, capped at 20 per profile, newest first. Disposable data: an unreadable file reads as empty and the next write replaces it; entries whose folder is gone are hidden, not deleted. Without an app config folder the list lives in memory for the app run (no temp-dir fallback, see `session-model.md`). `recent_projects_touch` canonicalises (`external_open::canonical_folder`), and so does `open_project`'s folder picker — tab paths and recent entries must be in the same form, or a folder picked through a symlink would not match its open tab.
- `live.js` records a recent only after a successful spawn (`_startProjectSession`, and a profile switch's respawn), and keeps `recentProjects` for the *active* profile only (`_syncRecentsProfile` on activation, last-tab close, profile refresh). All recents IPC runs through one queue (`_recentsCall`): the backend's `list` is unlocked, so unordered calls could let a stale list overwrite a newer touch. The strip menu shows `recentRows(recents, sessions, activeProfileId)` — entries already open as tabs are hidden.
- `openSession` always spawns; the new-project modal and `openProject` (a recent row) focus an existing tab first (`findProjectTab`), and `resumeSession` matches the registry's `sessionFile`, seeded with the resume path and refreshed from `get_state` while the tab is active; `/new` and a profile respawn clear it (`_freshConversationFields`).
